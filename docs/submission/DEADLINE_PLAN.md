Use this if faithful applicability cannot be connected within the integration timebox. Do not relabel a synthetic evaluator example as real manufacturer applicability.

Add only if connected and verified by feature freeze: small fact form; accepted W02 evaluator adapter; immutable before/after reassessment; basic JSON/Markdown export.

Deferred: general document import/OCR; extensive product/BOM management; evidence-request workflow; arbitrary document-version impact analysis; multi-model routing; five-view application; broad collaboration/admin UI; complex report design; managed production migration and broad hosted acceptance. Retain the original roadmap. Deferred features and full original W04/P3–W10 acceptance are not silently declared done.

## Review policy for the deadline scope

Block release for a broken advertised journey; unproven runtime integration; incorrect source/citation semantics; invented unknowns; automatic model-to-accepted-rule activation; exposed credentials/private files; broken authorization on exposed actions; data loss on the demonstrated path; unusable judge access; missing required submission items.

Do not block the reduced release solely for absent deferred features, cosmetic polish, broad scale testing, or generic architecture ambitions. Fix isolated defects directly in Codex after the worker stops when quicker; record the change and run affected checks. Consolidate substantial defects into one scoped repair. Reuse accepted evidence for unchanged behavior; run changed-path regressions plus one final end-to-end check. Do not remove existing tests or hide failures.

## Submission gates

- R1: stated journey works in the actual build against the actual backend; no placeholder actions presented as working.
- R2: real Nemotron/Nebius evidence belongs to the shipped runtime path, not merely an unrelated old spike. Live/cache/mock labels are accurate; no extra paid calls authorized here.
- R3: citations, selected coverage, unresolved states and explicit review are correct. Applicability claim requires faithful supported AST and facts; otherwise use the fallback.
- R4: exposed routes enforce their scope; no secret/provider key in browser, repository, video or public payload; old data/evidence preserved.
- R5: one chosen working demo/hosted application/test build is accessible for free judging with tested instructions. Full hosted P2 is required only if claiming that hosted architecture has passed, not for a local test build.
- R6: public code with open-source license/setup, public YouTube video under three minutes, track/description/tool feedback/testing details and working links are complete.
- R7: submit before the official deadline and verify the actual confirmation. A saved draft is not a submitted entry.
